# MCP servers through Executor

Claude Code and Codex reach company services (Cloudflare, Supabase, Vercel, PostHog) through one
[Executor](https://github.com/UsefulSoftwareCo/executor) instance instead of per-project entries. Executor holds the
logins; each project gets one entry pointing at its company's scoped connection.

```
Claude Code / Codex ──> Executor ──> [laiki] Cloudflare, Supabase prod, Supabase staging, Vercel, PostHog
                                 └─> [lab1095] Cloudflare, Google juan, Google ferramentas, Slack juan
```

Research and the v1/v2 comparison: [research-2026-11-02.md](research-2026-11-02.md). Gmail, Calendar and Drive per
Workspace domain: [google-workspace.md](google-workspace.md). Slack per workspace: [slack.md](slack.md). Original handoff:
[HANDOFF-2026-11-02.md](HANDOFF-2026-11-02.md).

## What lives here

- `apps/<company>/<service>/`: one folder per Executor app (`index.ts` plus `package.json`). Each defines the upstream
  MCP URL, the login (OAuth via dynamic client registration), and the approval rule. No secrets.
- The Executor version pin is in `../mise/config.toml` (`github:UsefulSoftwareCo/executor`, plus
  `experimental = true` and the `DO_NOT_TRACK` / `EXECUTOR_NO_UPDATE_CHECK` opt-outs).

Not here, by design: logins and tokens (inside Executor), connection IDs (generated per instance).

## Naming

- Apps: `[company] Service env`, e.g. `[laiki] Supabase prod`. Internal slug follows: `laiki-supabase-prod`, same as
  the folder `apps/laiki/supabase-prod`.
- Accounts (logins): `[company] Service env - access`, e.g. `[laiki] Supabase prod - read only`.
- Connections: the company (`laiki`, `lab1095`), plus `<company>-comms` for mail, calendar, Drive and Slack.
- Client entries: `executor-<company>`.

No approval prompts: Codex routines run unattended and a prompt stalls them. Instead, irreversible actions return
`denied` from the app's approval rule (Executor reports `ToolBlocked`, HTTP 403). Limits that matter most come from the
logins themselves (read-only Supabase prod and Laiki Cloudflare tokens).

Communication (mail, calendar, Drive, Slack) gets its own connection so a project can have infrastructure without it, or both.

The Executor management app stays off in both. URLs use `&elicitation_mode=browser` so approvals open in the browser
and the agent cannot approve its own calls (the mode is fixed when a client first signs in).

## Runbook

Install and start (Mac). Executor v2 has no OS service; `launchd/dev.juan.executor.plist` runs `executor service start`
at login (install: copy it to `~/Library/LaunchAgents/` and `launchctl bootstrap gui/$(id -u)` it; log in
`~/Library/Logs/executor-launchd.log`):

```sh
mise install                      # Executor from mise/config.toml
executor service start            # http://127.0.0.1:4312, does not survive reboot
executor                          # opens the dashboard; prints a one-use #pair link
executor pair                     # new dashboard sign-in link for another browser (5 minutes)
```

Create every app from `apps/` (skips existing ones), or push folder changes to all of them:

```sh
~/dotfiles/mcp/bootstrap.sh            # create missing apps
~/dotfiles/mcp/bootstrap.sh --update   # also commit and deploy existing apps from their folders
```

The same by hand, for one app:

```sh
executor apps create --name "[laiki] Vercel" --files ~/dotfiles/mcp/apps/laiki/vercel   # prints the id
executor apps source --app <id> | jq -r .revision.commit                                 # current commit
executor apps commit --app <id> --files <dir> --expected <commit> --message "..."        # save a change
executor apps deploy --app <id> --commit <new-commit>                                    # make it live
```

Changing a provider definition (name, scopes, hosts) creates a new provider: the app needs a new login.

Then, by hand in the dashboard: link each app's account (Accounts tab, Connect new account, sign in with the right
browser profile), create the connections above, and add `executor-<company>` to each project:

```sh
claude mcp add --transport http executor-laiki '<connection url>'    # or edit .mcp.json; then /mcp, Authenticate
codex mcp add executor-laiki --url '<connection url>'                # starts the login itself
```

Known issues (beta.34): the dashboard can show a blank page after an OAuth redirect (Vercel did once; retrying from a
freshly loaded dashboard worked). The Apps list shows "No accounts linked" for app-scope accounts; the app's Accounts
tab is accurate.
