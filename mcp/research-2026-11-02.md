# Executor research note

Checked: 2026-11-02 (read-only: docs, GitHub releases, npm registry, ghcr, source at tags; nothing installed)

Repo: https://github.com/UsefulSoftwareCo/executor (formerly RhysSullivan/executor). Site: https://executor.sh

## Two products under one name

- **v1** is the stable release: `v1.6.11` (2026-10-22), `main` branch, npm `executor@latest`, docker `:latest`
  (same digest as `:1.6.11`). Its docs exist only in the repo under `apps/docs/` at tag `v1.6.11`.
- **v2** ("Executor 2") is a ground-up redesign in beta: `executor@2.0.0-beta.34` (2026-10-31, commit
  `8861ecc1624566fa8670bc4b3bada90c84f8a008`), `v2` branch, npm `executor@beta`, docker `:beta`. The live docs at
  https://executor.sh/docs already describe v2.
- Commits on `main` since 2026-10-23 are mostly about freezing Cloud orgs and forwarding them to v2 (#2287, #2337,
  #2356, #2388). v1 is being wound down. There is no local v1 to v2 migration (only a Cloud import script).
- The handoff's facts (port 4788, stdio `executor mcp`, toolkits, per-tool policies, `EXECUTOR_SECRET_KEY`) are
  all v1.

## License and cost

MIT (`LICENSE` at both tags; GitHub reports spdx MIT). https://executor.sh/pricing lists Cloud tiers only (Free,
Team $15/member/month, Enterprise). No license-key gating found in local or self-host source.

## Comparison

| Topic | v1 (1.6.11) | v2 (2.0.0-beta.34) |
| --- | --- | --- |
| Install | npm `executor` (Node launcher plus Bun-compiled binary in optional deps); GitHub zips/tarballs with binary plus sidecars (`libsql.node`, `keyring.node`, `workerd`, wasm, ...) | npm `executor@beta --include=optional`; curl `https://executor.sh/docs/install.sh`; Homebrew `usefulsoftwareco/tap/executor-beta`; GitHub `executor-<ver>-<os>-<arch>.tgz` with `package/executor` plus SHA256SUMS. No Node or Bun at runtime |
| mise | `"github:UsefulSoftwareCo/executor"` with explicit `asset_pattern` per platform (avoid the `executor-desktop-*` asset), or `"npm:executor" = "1.6.11"` (exact pin, needs node >= 20) | `github:` backend with `version_prefix = "executor@"`, `prerelease = true`, exact pin |
| Local server | `executor daemon run` / `executor web` on 4788; `executor install` registers launchd `sh.executor.daemon` on **4789**. Live port in `~/.executor/server.json` | `executor` / `executor service start` on 4312. No OS service: does not survive reboot |
| Client auth | Bearer token in `~/.executor/server-control/auth.json` (0600); `executor server rotate-token` | API key in Keychain (`com.usefulsoftware.executor.v2`) or keys.json; `executor rotate-key`; browser sign-in for clients |
| Stdio | `executor mcp` (bridges to daemon over HTTP, cannot be scoped to a toolkit) | Removed |
| Per-company sets | Toolkits: `/mcp/toolkits/<slug>` (`apps/local/src/mcp.ts` line 117). Created in UI or `POST /api/toolkits`; no CLI. Deny by default, connection patterns grant, toolkit policies narrow | Scoped connections: `/mcp?connection=<id>`, created on the dashboard Connect page; pick account per app and tools (all, read-only, picked) |
| Two accounts, one upstream | One integration, many connections (`concepts/connections.mdx`): "the same API authenticated for two different accounts". Tools addressed `<integration>.<owner>.<connection>.<tool>` | One linked account per app slot; docs: "copy the app and link one to each copy" (`connect-an-account.mdx`) |
| OAuth | Executor is the client (RFC 7591 DCR or manual). Callback `<EXECUTOR_WEB_BASE_URL or http://localhost:port>/api/oauth/callback` | Callback `<BETTER_AUTH_URL>/api/oauth/callback`; optional `EXECUTOR_OAUTH_CALLBACK_URL`, `EXECUTOR_OAUTH_CLIENT_METADATA_URL` |
| Policies | `approve`, `require_approval`, `block` on patterns like `supabase.*.prod.*`; most restrictive wins; UI, built-in tools, or per toolkit | Declared in app TypeScript (`always()`, `never()`, function, `withApprovals`). Dashboard MCP apps default to "ask before destructiveHint tools" |
| Secrets/state | DB `~/.executor/data.db`; OAuth tokens default to a **plaintext 0600 JSON file** (`$EXECUTOR_DATA_DIR/auth.json`, service sets `~/.executor`), Keychain only for explicit refs | Data in `~/.executor/v2/cli`; keys in Keychain or keys.json |
| Declarative config | `executor.jsonc` covers integrations and plugins, not connections, policies or toolkits; at 1.6.11 only `plugins` is read at boot. No export/import | Apps are git-backed TypeScript (`executor apps create/commit/deploy --files <dir>`), so app definitions and approval rules can live in dotfiles. Accounts and scoped connections are dashboard/API state, no export |
| MCP surface | Default `codemode` (one `execute` tool); `?mode=passthrough` gives `integrations`, `skills`, `search`, `invoke`. No direct upstream tools | `skills`, `search`, `describe`, `call`, `execute`, `resume`. No direct upstream tools |
| Self-host | `ghcr.io/usefulsoftwareco/executor-selfhost:1.6.11`, port 4788, volume `/data`, env `EXECUTOR_WEB_BASE_URL`, `EXECUTOR_TRUSTED_ORIGINS`, `EXECUTOR_SECRET_KEY`, `BETTER_AUTH_SECRET` | `:beta` / version tag, port 4400, volume `/app/data` (PGlite), env `BETTER_AUTH_URL`, `EXECUTOR_ENCRYPTION_KEY` (64 hex) |
| Client registration | Docs show `npx add-mcp`; bearer header needed but undocumented | `claude mcp add --transport http --scope user executor '<origin>/mcp'`; `codex mcp add executor --url '<origin>/mcp'` then `codex mcp login executor` |

## Risks

- Any v1 setup (toolkits, policies, stdio) will be redone when v2 goes stable; v1 local data is not migrated.
- `:latest` docker tag will presumably flip to v2. Always pin a version tag.
- v1 local stores OAuth tokens in plaintext JSON by default; CLI and service default to different data paths and
  different ports; a foreground daemon derives its workspace from the cwd.
- v1 `executor install` writes the versioned binary path into the launchd unit: rerun after every mise bump.
- v2 checks npm daily (`EXECUTOR_NO_UPDATE_CHECK=1`) and sends anonymous analytics (`DO_NOT_TRACK=1` or
  `EXECUTOR_DISABLE_ANALYTICS=1`).
- Neither version exposes upstream tools directly; agents always go through search/invoke or code mode.
- Still unverified: OAuth against Cloudflare, Supabase, Vercel, PostHog; DCR acceptance of a `*.ts.net` callback.
